# 二校区琴房管理系统 V2.0（2024 C 语言大作业升级版）

> 课程项目 / 独立演示软件。此项目**不连接**学校的琴房预约后台，不代表学校官方系统。软件中的20间琴房、开放时间、登记字段、公告均来自原始仓库（`legacy/`），用于复现**当年的项目场景**，并不表示已经核实当前学校实际情况。

## 1. 主要改造

- Windows 可用的中文桌面图形界面（Tkinter + ttk），包括总览、注册、预约、签到签退、我的预约、使用公告六个页面。
- 保留原作的默认业务规则：**琴房1～20号；北京时间07:00～22:00；每段1小时（07～21点共15段）；整点后的第30分钟起不允许再约当前时段；只预约当日；注册→预约→签到→签退**。
- 修复原始 C 版本的缓冲区和数组越界隐患、读档日期指针运算错误、预约与签到状态不持久化、跨日房间占用状态错误、未初始化数据等问题。
- 将全局数组 + 三个脆弱 TXT 文件改为 SQLite（Python 标准库自带）；预约房间/学生时段冲突由数据库唯一约束保证，支持不同进程使用同一数据库。
- 学生密码改为 PBKDF2-SHA256 随机盐哈希存储，不再以明文直接持久化。
- 记录签到、签退时间及状态；按**预约结束时间**计算超时提示；历史记录可按身份查询。
- 提供原有文本数据的一次性导入工具和安全数据库备份工具。

### 主要的兼容性取舍

- **技术语言变化**：原版是单文件 C 命令行程序；V2 的业务层与 UI 改为 Python 标准库实现，以便在 Windows 上无需第三方依赖就能运行图形界面。原始 `main.c` **未修改且原样保存在 `legacy/`**，方便比照；并非声称仍由 C 语言驱动新版核心。
- 旧版签退只检查姓名/学号，V2 额外验证密码，避免别人冒用身份；操作流程不变。
- 旧版没有可靠的签到时刻/签退状态存储，因此这部分**无法从旧 TXT 中恢复**。
- 签退**不会释放原时段的预约占位**，避免其他人错误地抢占同一时段；预约记录没有开放取消入口，维持原业务流程。
- 不擅自添加提前签到分钟限制、违规处罚机制、管理员审批等未在原项目中实现的校规；签到成功仍提示不得提前进入。
- 旧版最多保存2000条预约记录是数组大小的技术限制，V2改为数据库历史记录，不再受该意外技术限制；**学生注册上限2000**仍保留。

## 2. Windows 上如何使用（推荐）

1. 下载本项目 ZIP，**解压整个文件夹**（不要只解压 `app.py`）。
2. 安装 [Python 3.10 或更新版本](https://www.python.org/downloads/windows/)；安装时勾选 **Add Python to PATH**。标准 Windows Python 安装包包含 Tkinter。
3. 双击 `启动琴房系统.bat`，即可弹出图形界面。首次启动时会自动创建空数据库。
4. 依次打开左侧 **学生注册 → 预约琴房 → 签到与签退** 页面；“我的预约”可查历史。

如果双击启动有问题，打开 PowerShell，进入项目文件夹后执行：

```powershell
py -3 app.py
```

不需要 `pip install`：**所有运行依赖均来自 Python 标准库**。

## 3. Linux / macOS

需要有 Python 3.10+ 和 Tk 支持（Ubuntu 可安装 `python3-tk`），然后运行：

```bash
python3 app.py
```

本项目的时间以**北京时间 UTC+8**解释，因此即使电脑在其他时区，也按二校区的时段规则处理。请确认系统日期和时间准确。

## 4. 数据保存在哪里？

默认保存在以下路径（自动创建）：

- Windows: `C:\Users\你的用户名\.hit_piano_rooms_v2\piano_rooms.sqlite3`
- Linux/macOS: `~/.hit_piano_rooms_v2/piano_rooms.sqlite3`

学生和预约不再分别存储于原先的三个 TXT。**删除该数据库会丢失新版注册与预约记录**，请勿随意删除。

### 手动备份（无需关闭界面）

```powershell
py -3 backup_database.py --out "D:\piano_backup.sqlite3"
```

可附加 `--db "路径"` 来指定其他数据库；目标已存在时会拒绝覆盖，避免误操作。

## 5. 导入你以前的 TXT 文件（可选）

原仓库仅有 `main.c` 和 `README.md`，**没有**提供当年的 `.txt` 真实数据。如果你自己的电脑上还有：

- `students.txt`
- `reservations.txt`
- `pianoRooms.txt`

将它们放在同一个目录（例如 `D:\old_piano`），再执行：

```powershell
py -3 migrate_legacy.py --source "D:\old_piano"
```

工具只**读取**原数据，不会删除或修改原文件。能识别的学生和日期正确、未冲突的预约会导入，并报告成功/跳过数量。旧预约时间段序号 **1→07:00，...，15→21:00**。旧 `pianoRooms.txt` 只有占用标记、没有日期，还可能由错误写入导致越界，因此**故意不从它重建占用**，统一按有效预约记录推算。已经导入的记录再次导入会被跳过，不会重复创建。

⚠️ 原 C 程序本身没有正确保存签到/签退状态，故不能凭旧 TXT 猜测这些状态；导入的预约统一标记为“已预约”。强烈建议导入前先执行备份命令。

## 6. 测试和开发

```bash
python -m unittest discover -s tests -v
```

另外可在带图形桌面的环境执行 `python tests/smoke_gui.py` 检查各页面；若使用无桌面 Linux，需 `xvfb-run -a python3 tests/smoke_gui.py`。

目录结构：

```text
HIT_Piano_Rooms_V2/
├── app.py                    # 启动入口
├── 启动琴房系统.bat             # Windows 双击启动
├── piano_manager/
│   ├── config.py             # 源于原作的校区规则与原始公告
│   ├── database.py           # SQLite 数据结构与初始化
│   ├── service.py            # 注册、预约、签到、签退与鉴权
│   └── ui.py                 # Tkinter 图形界面
├── migrate_legacy.py         # 原 TXT 导入
├── backup_database.py        # 数据库备份
├── tests/                    # 自动化用例与 GUI 冒烟测试
├── screenshots/              # 界面预览（在模拟时间下截取）
├── legacy/                   # 原始 C 项目完整代码与 README
└── 改造说明.md                # 与老版本的关键问题对照
```

## 7. 一些刻意保留的边界

- 原版仅能预约**当天**，所以 V2 不提供未来日期选择。
- 原版**没有**预约后取消、排队候补、管理员账号、自动处罚、学校统一身份认证，这些不应被暗中加入。
- 原项目的20个琴房号是**代码设定**，不是对学校当前琴房数量的现场核实。
- 该版本是本地课程项目演示，不支持跨电脑实时共享或连接官方校务数据。多个窗口操作同一个本机数据库时，数据库约束可防止冲突。
