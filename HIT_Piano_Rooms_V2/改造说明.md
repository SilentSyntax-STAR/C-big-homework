# 旧版 main.c 与 V2.0 关键改动对照

本说明依据你上传的原始 `main.c`（726行）及原始 `README.md`。原代码放在 `legacy/main.c`，未在原件上做不可逆修改。

| 旧版位置 | 可复现或可从源码确认的问题 | V2 解决方式 |

| 146-156, 192-197, 485-487 | 多个 `scanf("%s", ...)` 未给缓冲区长度，长输入可能越界 | Tkinter 输入框 + 业务层长度/格式检查，数据库参数化语句 |

| 313-316, 329-340 | `timeSlotIndex` 在 `timeSlot` 赋值前赋值；`Reservation` 未整体初始化；记录上限判断后仍可更新房间占用 | 数据库字段有确定默认值，预约状态和预约记录同一条原子写入 |
| 338-340 | 预约成功后没有调用持久化保存函数 | 每次预约立即提交 SQLite 事务 |

## 业务层明确未随意改变的地方

1. 编号1～20、早7点至晚10点、一天15个一小时的预约时段。
2. 当日预约，30分钟截止当前时段（到 HH:30 即不能预订 HH:00–HH+1:00）。
3. 五项学生信息：学号、姓名、班级、乐器、密码。
4. 注册→预约→签到→签退的主要交互流程与公告原文。
5. 签到成功仍提示不得提前进入；没有擅自增加签到时间窗口规定。

## 透明说明的改动

- 修复双重占用：同一个琴房同一日期同一时段不能重复预约；同一学生在同一时段不能多次约不同琴房。旧版只处理第一种；新增第二种为避免同一人占掉多个琴房的基础数据一致性约束，并非声称来自学校官方规定。
- 原来签退仅需姓名学号，现在为了避免身份冒用，要求验证密码；这是**有意的安全增强**。
- 预约时仍先确认再提交；注册学生上限仍为2000，但预约历史记录改为数据库，避免原代码2000条固定数组的意外限制。
- 旧版只保留一个 `isSignedIn`，没有可恢复签退的字段；新版历史状态更明确。
- 软件**未接入**学校真实琴房/学工认证系统，显示的可预约房间是该软件自己的本地演示数据。
